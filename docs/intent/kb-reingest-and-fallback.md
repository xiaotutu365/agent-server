# 意图声明：知识库重新入库 + 检索失败兜底

- 确认时间：2026-10-17
- 确认方式：interview-me 对话（用户逐项确认 A 组范围与留档方案）

## Outcome

知识库两项体验补齐：

1. **文档重新入库**：文档列表每行加「重新入库」按钮——删除该文档旧片段，从留档原文件按当前分片策略重新切分入库，免去"删除→重传"。
2. **检索失败兜底**：embedding 服务不可用时，混合检索自动降级为纯 BM25 关键词检索，并在结果中标注降级原因。

## User / Why now

- 用户：知识库管理员。
- 动机：调整分片策略后旧文档需"删除→重传"，摩擦真实存在；embedding 挂掉时检索完全不可用、直接报错。

## Success

- 改分片策略 → 点「重新入库」→ 该文档片段按新策略重建成功。
- 停掉 embedding 配置后检索仍返回 BM25 结果，并明确提示已降级。

## Constraint

- 留档方案（已确认）：上传时保存原文件到 `data/uploads/{kb_id}/`，仅对**新上传**文档生效；旧文档（无留档）删除重传一次后自动纳入留档。
- 「重新入库」仍需 embedding 在线（重建需重新向量化）；不可用时返回明确错误。
- 留档目录不进 git（已在 .gitignore 覆盖 data/）。
- 同库同名文档重复上传覆盖留档（以最新版为准）。

## Out of scope

- B 组评测深化（TestsetGenerator 自动评测集、生成层指标）——下一阶段。
- 全库一键重建（沿用既有决策，仅按单文档粒度重建）。
- 扫描件 OCR。
- pdf/docx 上传已实现（pypdf/python-docx 已装、前后端已放开），仅顺手冒烟验证，不改造。
