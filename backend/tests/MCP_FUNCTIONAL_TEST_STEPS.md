# MCP 功能测试 · 详细步骤（落盘记录）

> 目标：通过后台 UI 挂载 MCP 服务器 → 聊天端到端调用工具 → 验证权限闸（allow_roles）。
> 配套：`tests/MCP_PERMISSION_TEST_STEPS.md`（权限闸单测示例）、`tests/test_mcp_permission_demo.py`。
> 本文为**手动 UI + 聊天**的功能测试；自动化单测见 `tests/test_mcp_*.py`。

---

## 0. 前置条件

1. 后端在 `:8000` 健康：`GET http://localhost:8000/api/health` 返回 `{"status":"ok",...}`。
2. 前端在 `:5173` 可访问：`http://localhost:5173`。
3. 用**管理员**账号登录（默认 `admin` / `admin123`）。
4. 后端进程是**重启过**的（FastAPI 无热重载，角色/部门表与 users 新列在启动时才建）。
5. 测试服务器脚本可用（相对 `backend/` 目录）：
   - `tests/mcp_demo_server.py`：工具 `crm_ping(message)`、`add(a, b)`
   - `tests/mcp_test_server.py`：工具 `echo(text)`、`add`、`search_items` 等

## 2. 用例二：聊天中端到端调用 MCP 工具

**用例编号** F-02 ｜ **预期**：模型调用 `crm_ping`，返回真实结果，工具真正执行。

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 2.1 | 进入聊天页（首页「对话」或对应入口） | 聊天窗口 |
| 2.2 | 发送：`请调用 crm_ping 工具，给消息填 "hello"` | 触发工具调用 |
| 2.3 | 观察事件流 | 出现 `tool_start`（工具名 crm_ping）、`tool_end`（结果） |
| 2.4 | 看最终回复 | 包含 `crm_ping` 的真实返回（如 `pong: hello` 之类） |

> 若模型没调工具：明确提示工具名，或换更直白的话术（如「用 crm_ping 工具回显 hello」）。
> 也可测 `add`：发送「用 add 工具计算 3 加 5」→ 返回 `8`。

## 3. 用例三：权限闸（allow_roles）

**用例编号** F-03 ｜ **预期**：`allow_roles=admin` 时，管理员可用、普通用户被拒。

### 3.1 设闸
| 步骤 | 操作 | 预期 |
|---|---|---|
| 3.1.1 | 回到「MCP 服务器」页，默认 Agent，点 `demo` 卡片「**编辑**」 | 弹窗 |
| 3.1.2 | allow_roles（逗号分隔）：填 `admin` | — |
| 3.1.3 | 点「测试连接」 | 仍「连接成功，暴露 2 个工具」（连接不看角色） |
| 3.1.4 | 点「确定」→ 底部「保存并热重建」 | 「已保存并热重建 ✓」；卡片出现「限角色: admin」badge |

### 3.2 管理员调用（应通过）
| 步骤 | 操作 | 预期 |
|---|---|---|
| 3.2.1 | 用 **admin** 账号聊天，发 `请调用 crm_ping 工具，消息 hello` | 工具执行，返回真实结果 |

### 3.3 普通用户调用（应被拒）
| 步骤 | 操作 | 预期 |
|---|---|---|
| 3.3.1 | 退出，用**普通用户**账号（role=user）登录 | 进入聊天 |
| 3.3.2 | 同一句话触发 `crm_ping` | Agent 收到 `⛔ 无权限：MCP 服务器「demo」的工具仅允许角色 ['admin'] 调用，当前角色为 user。`；**工具不执行** |

### 3.4 自动化等价验证（可选，免登录）
```bash
cd backend && ./venv/bin/python -m pytest tests/test_mcp_permission_demo.py -v
```
预期 5 条全绿（2 allow / 3 deny）。

## 4. 用例四：SSE / Streamable HTTP 方式（可选）

**用例编号** F-04 ｜ **预期**：HTTP 类传输也能挂载并调用。

1. 另开终端，启动一个 HTTP 暴露的 MCP 服务器：
   ```bash
   cd backend
   set MCP_TRANSPORT=sse
   .\venv\Scripts\python.exe tests/mcp_test_server.py
   ```
   默认监听 `127.0.0.1:8001`，SSE 路径 `/sse`（Streamable HTTP 为 `/mcp`）。
2. 后台「MCP 服务器」→ 新增：
   - 传输方式：`SSE`（或 `Streamable HTTP`）
   - 服务器地址 URL：`http://127.0.0.1:8001/sse`
   - 请求头（可选，如服务端需鉴权）：`Authorization: Bearer xxx`
   - allow_roles：留空
3. 点「测试连接」→ 应暴露若干工具。
4. 确定 → 保存并热重建 → 聊天触发验证。

## 5. 用例五：失败与边界

| 用例 | 操作 | 预期 |
|---|---|---|
| F-05a 命令错误 | 启动命令填 `pythonxxx`（不存在）后「测试连接」 | 连接失败并提示错误（不崩溃） |
| F-05b 重复名称 | 新增时名称仍填 `demo` | 校验报错「服务器名称已存在」 |
| F-05c 删除 | 点 `demo` 卡片「删除」→ 确认 | 列表移除；再「保存并热重建」后 Agent 不再有该工具 |

## 7. 常见问题排查

- **工具没挂上**：后端是否重启过？选中了正确的 Agent？保存时是否点了「保存并热重建」（不只是「确定」）？
- **普通用户仍能调用**：`allow_roles` 是否含 `admin` 且保存热重建成功；确认普通用户 JWT `role=user`（自定义角色会被归一为 user）。
- **测试连接超时**：脚本路径/命令是否正确；stdio 用相对 `tests/...` 时后端工作目录须在 `backend/`。
- **⛔ 无权限 文案不同**：网关比对的是 `user_ctx` 里的 `role` 字符串（admin/user），不是 `role_id`。
